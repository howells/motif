## The finding that matters: a previous 3/3 was wrong

**Error Handling scored 3/3 on 2026-07-11. It should not have.**

`motif tool run` with no argument exited **1** with `error: missing required argument 'tool'` in plain text, *even under `--format json`*. Two contract violations at once: the catalogue reserves exit 1 for "unknown" and documents 2 for bad input, and every other invalid-input path emits RFC 7807. An agent branching on exit 2 never fired; an agent parsing stdout as JSON got a parse error instead of a diagnosis.

The path was never tested and never scored. The audit read `error-catalog.ts`, the `handleError` call sites and the documented mapping - all correct - and concluded the dimension was complete. **Commander's own failure path was upstream of all of it.**

Fixed today (MOT-39): a shared helper routes `CommanderError` through the envelope, `--help` and `--version` still exit 0, and Commander's message survives into `message` rather than being replaced by something generic.

### What this says about the method

Scoring by reading the implementation finds what the implementation does. It does not find the paths that never reach it. Three of today's defects were of that shape - a price that contradicted the vendor, output keys the vendor had renamed, arguments that existed but were never advertised - and none was visible from source.

**Recommendation for the next audit: exercise each dimension's failure path, not only its happy path.** For Error Handling that is one command per error class with the exit code checked. It would have taken a minute and would have caught this in July.

## Findings

### Cluster A: Testing has breadth without statistics

The gap named in July - a scored eval dataset - is unchanged. Today added substantial coverage but none of it is what the rubric means by level 3.

| Severity | File | Issue | Dimension |
| --- | --- | --- | --- |
| Medium | `apps/cli/tests/` | 248 tests, all deterministic; no pass@k or pass^k | Testing 2→3 |
| Medium | (absent) | No eval framework, no multi-run cases, no baseline comparison | Testing 2→3 |
| Low | `.github/` | No CI job runs the drift guards even in opt-in form | Testing |

**Worth recording as a new category the rubric does not cover.** Four guards added today verify claims against an **external source of truth** rather than against fixtures:

- `registry-drift.test.ts` - every entry's output keys against fal's live OpenAPI
- `tool-parameters.test.ts` + `sync-tool-parameters.mjs --check` - the generated argument surface against fal's schemas
- `benchmark-price-fields.test.ts` - structural: no price-shaped field may live in a model's benchmark block
- `verify-demos.py` - every documented demonstration must measurably show its effect

That last one exists because a documentation page claimed a restoration had recovered detail when measurement showed an 8% change - noise. These are not evals, but they catch a failure class evals do not: **a fixture cannot tell you the vendor changed under you.**

**Approach:** the honest route to 3/3 is a small scored dataset over the promoted verbs - twenty cases, three runs each, pass^k on structural correctness (did `segment` return a mask, did `ask` return a non-empty answer) rather than image quality. That gates regressions without needing a model grader.

## What changed since 2026-07-11

Score-neutral, but the surface is materially larger:

- **Tool Design**: registry 22 → 71 entries. Every argument each endpoint accepts - 386 - generated from fal's OpenAPI rather than hand-written, with `--check` failing when fal moves. What each model *returns* measured from real bytes, with lossless availability derived from the measurement plus the accepted arguments rather than stored a third time.
- **CLI Design**: seven verbs (`segment`, `ask`, `erase`, `reframe`, `enhance`, `layers`, `vectorize`) as descriptors over one shared pipeline. Multi-file output, history recording, numeric cost, queue routing on a registry flag.
- **MCP**: 5 → 8 tools, `motif://tools/{id}` resource template, shared reply and validation helpers so new tools cannot grow a second convention.
- **Error Handling**: the commander hole above.
- **Discovery**: `docs/tools/` with five pages and twenty verified example images, each demonstration measured to prove it shows its effect.

Nine defects were found and fixed en route, plus four more after release (MOT-38 to MOT-42). Every one was a **confidently wrong value while the tests stayed green** - the worst a price encoded 33x over what the vendor charges. That pattern, not any single bug, is the durable finding: *the registry described the interface, not the artefact.*
