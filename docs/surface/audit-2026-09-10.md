# Surface Audit: Motif

**Date:** 2026-09-10
**Mode:** plan
**Previous:** 2026-08-24 (19/21 raw after MCP retirement, 27/30 scaled, Agent-first)
**Build audited:** `apps/cli/dist` at HEAD `2ddde1b` ("Replace creative flags with house looks and moods"). Working tree clean at audit time. Another session is changing CLI flags, `-e`, output paths, a new `motif sheet` command and gpt2 transparency; those areas are audited for intent, not for their half-finished state.
**Dimensions re-scored:** CLI Design, Discovery & AEO, Context Files, Error Handling, Tool Design, Testing. Authentication carried forward unchanged, not re-scored.

## Why this audit

Usage evidence from Daniel's transcripts, 604 agent-run `motif` commands:

| Signal | Count |
| --- | --- |
| Real uses of `segment`, `ask`, `erase`, `reframe`, `enhance`, `layers`, `vectorize` since shipping on 2026-08-23 | 0 |
| Real uses of `series` | 0 |
| The same capabilities reached through `motif tool run <id>` | 37 |
| Image grids hand-built with ImageMagick | ~418 |
| `INVALID_OPTION` failures (a flag the chosen model doesn't support) | 206 |
| Output-path sandbox failures | 64 |

The 2026-08-24 audit scored five of these dimensions 3/3 by reading the implementation. The previous audit's own method note asked the next one to check "who is on the other end of this surface, and are they there?" For the verbs and Series, nobody is. This audit scores what agents actually see and do.

## Hypothesis: nothing tells an agent what task each command is for

**Verdict: confirmed.** The one refinement: the task wording exists, but only a level below the surfaces agents read first. And the one task-labelled index agents do find, `motif tool list`, sends them past the verbs to `tool run`.

### What an agent sees first, in order

1. **Outside the repo (most of the 604 commands):** the `~/.claude/CLAUDE.md` block shows `motif "prompt" --og`, `--cover`, `--vary` and `--up`. No verbs, no `tool`, no `series`, no `--look`. `~/.claude/cli-tools.md` has no motif section.
2. **`motif --help`:** about 70 generation flags, then `Commands:` with a single entry, `motif studio`. It's hard-coded in `apps/cli/src/cli.ts:99-102`. The verbs, `tool` and `series` are routed in `apps/cli/src/index.ts:26-49` before Commander runs, so they never appear in help.
3. **`motif --describe --format json`:** ~142 KB (~35k tokens). The top-level description is "fal.ai image generation CLI". There's no task index. Each verb's `description` is a task sentence of 11 to 20 words ("Remove a prompted object from an image and fill the gap."), with no when-to-use, no when-not-to-use and no pointer to siblings such as `finegrain-eraser` or `bria-genfill`.
4. **Root `AGENTS.md`, "Using the CLI":** generate, dry-run, stdin, history, `series run`. No verbs.
5. **`llms.txt`:** names the seven verbs in one sentence, by name only.
6. **`README.md`:** the "What Motif Does" CLI bullet omits verbs and tools. The only task-framed block in the repo is the Fal Tools section at line 440 of 701 ("Take something out, put something back, recut").
7. **`apps/cli/AGENTS.md`:** verbs at line 501 of 633, framed by fal capability ("Seven fal capabilities have a verb of their own"). The Agent Invariants list mutating commands as "generate, upscale, rmbg, vary", again without verbs. The Series section is task-framed ("Consistent Styling Across Related Images"), but this file isn't in the npm package.
8. **`apps/cli/README.md` (the npm page):** 29 lines, five entry-point commands, no verbs.

### Would an agent that wants to remove something find `erase`?

| What the agent tries | What happens |
| --- | --- |
| Reads `--help` for "remove" | Finds `--rmbg` ("Remove background from last image"). `erase` isn't listed. |
| `motif remove "the car" street.png` | `INVALID_OPTION`, "too many arguments. Expected 1 argument but got 3", with the generic suggestion to run `--describe`. No did-you-mean, although the mechanism already exists for `RESERVED_PROMPT` (`cli.ts:383`). |
| `motif "remove the car" -e street.png -m <model>` | Runs a paid generation-model edit. Nothing points to `erase`. |
| `motif tool list --format json` | Finds `object-removal` with `task: "prompted object removal"` and `category: "erase"`. No `verb` field. The agent runs `motif tool run object-removal`, which matches the 37 `tool run` uses. |
| `motif grid a.png b.png` | Same "too many arguments" error. No grid or sheet command exists yet, so agents fall back to ImageMagick (~418 times). |

The task-to-command mapping exists in exactly two places: the README Fal Tools block and `docs/tools/*.md`. Neither reaches an agent working in another project.

### Tasks named in the brief

| Task | Command | Discoverable from a first-look surface? |
| --- | --- | --- |
| Remove an object | `erase` | No. Only in `--describe erase`, the README at line 452, and `apps/cli/AGENTS.md` at line 509 |
| Extend the canvas / change the ratio | `reframe` | No. Its description says "Reframe", not "extend", "outpaint" or "expand". `bria-expand` and `flux-outpaint` are only reachable by `tool run` |
| Split into layers | `layers` | Only by exact name |
| Keep a set of images consistent | `series` | Only in the unshipped CLI guide's heading. The `series` description is task-adjacent but sits in a 35k-token schema |
| Grid or contact sheet | none (`sheet` in progress) | No |

### `--look` / `--mood`: better, still one hop away

- `--help` shows `--look <id>  House look id, e.g. editorial`. "House look" is close to "our usual look".
- `--describe generate` gives every look a `label` ("Quiet editorial"), a `description` and its defaults. A dry run confirmed `motif "a kitchen" --look editorial` resolves to `flux2-pro` at 1:1 with the look's clause appended.
- A near-miss id (`--look usual-editorial`) fails with `details.availableIds` listing all twelve looks, so recovery takes one step.
- Root `AGENTS.md`, `llms.txt`, the README and `CONTEXT.md` all name looks.
- **Gap:** the global `~/.claude/CLAUDE.md` block, where most agents start, doesn't mention looks. An agent in another project asked for "our usual editorial look" will probably write "editorial style" into the prompt and never reach `--look editorial`. The surface is right. The first-look context is missing it.

## Dimension evidence

### 2. CLI Design - 3/3 to 2/3 (confidence: high)

- Holds: JSON when piped, NDJSON history, `--fields`, `--dry-run` on every mutation, stdin JSON, semantic exits 2/3/4/5 (probed: `INVALID_OPTION`, `INVALID_OUTPUT_PATH` and `UNKNOWN_TOOL` all exit 2 with RFC 7807 on stderr), input hardening (`../` and absolute paths rejected).
- Fails the 3/3 detection "SKILL.md or AGENTS.md ships with the CLI": `apps/cli/package.json` `files` omits `AGENTS.md`.
- `--help` is incomplete: 10 of 11 top-level commands are missing (`cli.ts:99-102`).
- An unknown command word falls through to Commander's "too many arguments" message rather than a command-aware error (`index.ts` routing plus `errors.ts:192-208`).

### 4. Discovery & AEO - 3/3 to 2/3 (confidence: medium)

- There's no public website, so web signals (JSON-LD, robots, content negotiation, well-known endpoints) are **not applicable**. Scored on repo-local and package discovery.
- Artifact layer passes: `llms.txt` has an H1, a summary, H2 sections and described links, and linked docs resolve.
- Capability layer fails the semantic validation rule. The surfaces advertise commands by name, and agents with a task can't reach the command. Measured result: zero verb uses over 18 days.
- The npm-installed consumer gets a 29-line README with no verbs and no task routing.

### 6. Error Handling - 3/3 to 2/3 (confidence: medium)

- Holds: `type`, `title`, `status`, `doc_uri`, `code`, `is_retriable`, fal request id as `instance`, and Commander failures routed through the envelope.
- Level 2 requires suggestions populated. On the two errors agents hit most, they aren't:
  - `INVALID_OPTION` from a capability mismatch (206 hits): `packages/motif-sdk/src/generate.ts:62-63` throws a plain `Error("<Model> does not support <option>")`. No `details.field`, no list of models that do support it, and the only suggestion is "Run 'motif --describe --format json' to inspect valid commands". The capability data needed for a real suggestion already sits in `--describe` `models.*.capabilities`.
  - `INVALID_OUTPUT_PATH` (64 hits): no `suggestions` at all. The catalogue entry has none either.
- An unknown command gets no did-you-mean (see above).

### 7. Tool Design - 3/3 to 2/3 (confidence: medium)

- Holds: typed input and output schemas, field descriptions, enums, `supports_dry_run`, `mutating`, verb-to-tool links (`erase.tools = ["object-removal"]`), 386 generated tool arguments, and `task`/`category` on every registry entry.
- Fails level 2's "Use when..." and "Do not use for..." test. Verb descriptions are 11 to 20 words with no disambiguation. For example, nothing in the schema says when `erase` ($0.024, leaves shadows) loses to `finegrain-eraser` ($0.27). That guidance lives only in `docs/tools/repair-and-restore.md`.
- There's no tool-to-verb link, so the registry routes agents to `tool run` instead of the verb.
- The registry is one flat list of 71 tools against a rubric guide of fewer than 10 per context. `category` exists, but there's no category-first discovery path.
- Wrong annotation: `ask` is `mutating: true` although it "writes no file and records no history".

### 8. Context Files - 3/3 to 2/3 (confidence: high)

- Holds: `AGENTS.md` as the baseline, `CLAUDE.md` as a symlink overlay, a package guide, `CONTEXT.md` domain language, three-tier boundaries, and friction-driven entries (`EDIT_PROMPT_SWALLOWED`, `RESERVED_PROMPT`).
- `apps/cli/AGENTS.md` is 633 lines, well over the 370-line audit tolerance. The task-relevant content (verbs, Series) is at lines 501 and 545, after cost tables and error catalogues.
- No task index in any context file.
- Not applicable: Cursor/Copilot rules (not used).
- Outside the repo, but load-bearing for consumers: the global `~/.claude/CLAUDE.md` motif block predates verbs, tools, Series and looks.

### 10. Testing - 2/3 to 2/3 (confidence: high)

- Holds: ~393 cases, `agent-fixtures.test.ts` spawning the real CLI, `docs-sync.test.ts` pinning model ids, error codes and look/mood ids into the docs, and live drift guards against fal's OpenAPI.
- Gap unchanged: no pass@k or pass^k, no multi-run cases.
- New, specific gap: no **routing** test. Nothing checks that an agent given a task and only the shipped surfaces picks the right command. That's the failure that shipped. `docs-sync.test.ts` checks that ids appear in docs, not that tasks lead to them.

## Findings

### Cluster A: Task routing is missing from every first-look surface

Agents with a task can't reach the command built for it, so capabilities go unused or are reached the long way.

| Severity | File | Issue | Dimension |
| --- | --- | --- | --- |
| High | `~/.claude/CLAUDE.md` (outside repo) | Consumer quick reference lists only generate, `--vary`, `--up`. No verbs, tools, series or looks | Context Files |
| High | `apps/cli/src/cli.ts:99-102` | `--help` lists only `motif studio` under Commands | CLI Design 2→3 |
| High | `AGENTS.md`, `apps/cli/AGENTS.md`, `llms.txt`, `README.md` | No task-to-command index; verbs listed by name or fal capability | Discovery 2→3, Context 2→3 |
| High | `apps/cli/src/commands/tools.ts` (tool list/describe) | Registry entries wrapped by a verb carry no `verb` field; agents land on `tool run` | Tool Design 2→3 |
| Medium | `apps/cli/src/index.ts`, `apps/cli/src/utils/errors.ts` | Task words (`remove`, `extend`, `grid`) as commands produce "too many arguments", with no did-you-mean | Error Handling, CLI |
| Medium | `apps/cli/src/commands/describe.ts` | No `whenToUse`/`notFor`/task synonyms per command; no top-level task index; `ask` marked `mutating` | Tool Design 2→3 |

**Approach:** define one task table in the SDK or CLI (task phrases, synonyms, command, sibling tools) and generate the AGENTS.md index, the `--help` command list, the `--describe` `tasks` block, the did-you-mean table and the tool-list `verb` field from it. A docs-sync test then pins it, the way model ids are pinned today.

### In flux (audit intent, re-check after the other session lands)

- **`motif sheet`**: directly answers the ~418 hand-built grids, but only if it goes into the task index, `--help`, and the did-you-mean table (`grid`, `montage`, `contact sheet`). A new command without those will repeat the verbs' result.
- **Output paths**: the recovery text for `INVALID_OUTPUT_PATH` should state the new rule and the nearest valid path.
- **`-e` flag**: `EDIT_PROMPT_SWALLOWED` is documented. If the flag grammar changes, update that error and its docs together.
- **gpt2 transparency**: capability errors should name the models that support `--transparent` (see Cluster B).
